导航下拉组：完整 WAI-ARIA 菜单键盘模式

main.jsx:958-1025 · NavGroupPanel
键盘可达ARIA menu可交互

试一试：Tab 聚焦「资讯汇总」→ ↓ 打开并聚焦第一项 → ↑↓ 循环选择 → Home/End 首尾跳转 → Esc 关闭并把焦点还给触发按钮。鼠标悬停同样可开（保留现有 hover 体验）。

现状 焦点困死
role="menu" 已声明，但：打开时焦点不移入菜单；↑↓ 无响应；Tab 会直接跑出菜单进入页面其他元素；Esc 关闭后焦点丢失。屏幕阅读器播报「菜单」后用户却无法用键盘进入——语义与行为互相矛盾。
建议 完整模式
打开即聚焦第一项；↑↓ 在项间循环；Home/End 跳首尾；Esc 关闭并焦点回触发按钮；aria-activedescendant 备选。若不愿承担完整 menu 模式成本，可降级为 disclosure（aria-expanded + 普通列表）——关键是语义与行为必须一致。

预期效果

  • 键盘用户可完成「打开菜单 → 选择 → 进入视图」全流程，无需鼠标
  • 通过 WAI-ARIA Authoring Practices 的 menu button 模式验收，屏幕阅读器不再被矛盾语义误导

搜索与筛选：旧结果驻留 + 过程可视反馈

main.jsx:257-272, 540-545 · Feed.jsx
SWR过程反馈可交互
/
共 3977 篇文献 正在更新，显示的是上次结果

按 /（页面任意位置，输入框聚焦时除外）即可聚焦搜索框——这正是 Feed.jsx:349 向用户承诺、但全代码未曾实现的功能（U1）。点击「模拟慢请求」观察：旧结果不消失、列表不闪空，仅顶部 2px 进度条 + 「正在更新」胶囊提示（P3/U5）。

实现要点：debounce 与 URL 序列化合为一步计算（现状是两段 effect 链）；请求期间保留旧 articles；进度条只在请求超过约 800ms 后出现（避免快请求闪烁）；失败时保留旧数据并提示重试，而非清空列表。

预期效果

  • 输入搜索词时列表不再瞬间清空（消除「闪空」），阅读不被打断；隧道抖动时页面不再像卡死
  • 慢网络下用户获得明确「系统正在工作」的信号，投诉式刷新（反复点刷新按钮）预计大幅减少
  • 搜索链路从「filters → 300ms → 序列化 → effect → 请求」四步缩短为两步，输入到请求的延迟更稳定

对比度按 WCAG 2.x 相对亮度公式计算（白底）。正文要求 ≥4.5:1，大字号（≥18.66px 粗体或 ≥24px）与 UI 组件边界 ≥3:1。#7d8592 两个标准都不满足（白底），#6b7280 提升至 ≈4.8:1。

除 tertiary 外，建议建立全量对比度校验表：重点核查 ① 关键词胶囊的 --tone-soft 底 + --tone-ink 字组合（15 个方向 × 4 个期刊组）；② 11-12px 徽章文字（已读/收藏/方向 chip）；③ 禁用态与占位符文字（可放宽至 ≥3:1 但需记录）。校验脚本可一次运行、纳入 CI，防止后续新增配色再次破线。

预期效果

  • 全站文字对比度 ≥4.5:1，通过 WCAG 2.x AA；低视力用户、投影与强光环境下可读性显著提升
  • 对比度校验纳入 CI，新增配色需过检才能合入——从「一次性修复」变为「持续达标」
